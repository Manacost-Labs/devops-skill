# Conversational mode preparation

1. Resolve the actual runtime, target owner and allowed registered tasks through
   authorized discovery. Respect existing organizational policy.
2. Prepare a concrete finite scope card for the requested mode. Group genuinely
   missing boundary questions; do not ask again for covered ordinary work.
3. Local `devops_mode.py prepare` and host card confirmation select planning only.
   `PLANNING_SELECTED` is never evidence of authenticated execution authority.
4. Have the independently protected owner issuer sign the reviewed broker grant.
   Its private key must be inaccessible to agent and broker. This platform does
   not supply an authenticated human-only chat signing service. If absent, explain
   that prerequisite instead of forging events, metadata or approval records.
5. Submit typed task calls through the pinned mTLS client. Reuse the finite grant
   within its task set, mode, expiry and operation budget without repeat questions.
   Exact additional admission remains required above the ceiling and for
   destructive/irreversible effects. Never fall back to direct argv execution.
6. “Safe” restricts the broker principal immediately when a protected client profile
   is configured. Report the remote acknowledgement; a local-only update is not
   remote revocation. Certificate aliases and overlapping grants share restriction.
7. Preserve original operation IDs/receipts on uncertain outcomes and reconcile
   actual state before further mutations. Do not treat restart as recovery.

See `autonomy-modes.md` and the complete runtime documentation at
[protected execution](../../docs/protected-execution.md). Hook trust, managed
settings, OS isolation and target IAM are externally provisioned controls, not
claims the model may authenticate for itself.
