# Policy applicability, inheritance and delegation

Read for a linked policy that does not apply, an unexpected winning setting, or an administration permission failure. Keep the problem distinct: permission to edit a GPO, permission to link it to an OU, and permission for a principal to read/apply it are different rights.

## Trace one policy to one affected identity

1. Confirm the exact user SID, computer SID, their current OUs, GPO GUID, setting and user/computer half, client build, logon/session and processing time. Capture client-selected DC and the user's actual token/group state. A group change may require a new logon or computer authentication context; membership shown in AD does not update an existing token.
2. Collect a fresh `gpresult /scope computer /r` in the appropriate elevated context and `gpresult /scope user /r` in the affected user's context, or protected HTML/XML reports for that target. Correlate GroupPolicy Operational and System events by the processing activity ID/time. An administrator's user report does not describe another user's session. Reports can contain private paths, names, scripts and settings: redact before sharing, and never execute report content.
3. With an explicit domain/DC, use `Get-GPInheritance -Target <exact-ou-dn>` to inspect direct and inherited links, enabled state, order, enforced links and block inheritance. Trace local/site/domain/OU processing, including the actual AD site. Within one container, link order 1 has higher precedence. Block inheritance does not defeat an enforced ancestor link. A linked/apparently inherited GPO is still subject to its applicability checks.
4. Check the GPO's enabled halves, security filtering and effective Read plus Apply Group Policy for the intended target, including explicit deny and nested groups. User policy retrieval also needs the computer's read access under current Windows behavior; distinguish read-only access from Apply. Examine WMI filter result on the actual client, loopback Merge/Replace and Group Policy Preferences item-level targeting. Preferences, tattooed settings and CSE-specific refresh/restart/logon requirements can explain a persistent value even after a GPO disappears.
5. Check both GPC and GPT replication on the DC actually used by the client using [replication-and-sysvol.md](replication-and-sysvol.md). Then inspect extension failures, network/startup timing, synchronous processing and conflicting management mechanisms. Do not use `gpupdate /force`, reboot, unlink/relink, broad filtering or disabled security as a diagnosis. A refresh can execute settings/scripts and needs approved target scope.

Verification must name the winning setting/value on the intended canary and show a denied or excluded principal does not receive it, after the necessary approved processing cycle. Capture the client DC, policy GUID/version and observation interval. Neither GPMC modeling nor a successful link/edit command proves live application.

## Delegation branch

Read the exact OU/object security descriptor and each affected GPO's `Get-GPPermission -Guid <guid> -All -Domain <domain> -Server <dc>` result. Resolve trustee SIDs, access masks/extended-right GUIDs, object-class/property scope, inheritance flags, explicit/inherited ACEs and deny entries. Check OU Create/Delete Child versus object Write Property rights, GPO edit versus link rights (`gPLink`/`gPOptions`), ownership and group nesting separately. Include protected-object/AdminSDHolder behavior and `adminCount` when inheritance unexpectedly differs; never reset protection or inheritance globally to make delegation work.

Prepare only the exact ACE delta, with its before-state, destination object/class and descendant scope. A generic OU permission template can grant escalation through password resets, group membership or GPO control. Verify using the delegated identity: one allowed action on an approved disposable canary and one meaningful denied action outside the scope. Admin success, an ACL listing or `-WhatIf` is insufficient. Restore only the changed ACEs under the same bounded recovery plan; do not replace a whole OU descriptor over unrelated concurrent changes.
