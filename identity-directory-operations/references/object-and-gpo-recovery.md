# Recover one AD object or GPO

Read before restoration. Object/GPO recovery is R4: bind the exact immutable target, artifact and method to the contract-v2 request, independent approvers where required, change lock, current window, backup/restore evidence and recovery owner. A request to diagnose does not approve recovery. Export the current state first, preserve concurrent evidence and confirm healthy replication; restoration of an object is not a domain-wide rollback.

For agent execution, these commands describe the planned method only. Platform 0.15 requires a protected administrator-registered immutable typed task, external signed grant and exact destructive R4 admission. Local gate output or unsigned approval metadata cannot authorize a native command. No such AD task is shipped here: absent that external capability, provide the exact recovery plan and keep execution blocked.

## Deleted directory object

Confirm the forest/domain GUID, writable DC, original objectGUID/SID, class, deletion time, `lastKnownParent`, `msDS-lastKnownRDN`, `isDeleted` and `isRecycled`. Query the exact GUID with `Get-ADObject -Identity <guid> -IncludeDeletedObjects -Server <dc> -Properties ...`; never pipe a wildcard result into restore. Verify the parent still exists and the original name is free. An alternate parent or name changes the plan and requires new approval.

Establish whether Recycle Bin was enabled **before** deletion and whether the object remains within the restorable deleted-object lifetime. Enabling Recycle Bin now does not restore previously stripped attributes and is itself a separate forest-wide, irreversible feature decision. A recycled/expired object, unsupported object class or missing retention evidence requires a topology/version-specific backup recovery handoff; do not guess a tombstone reanimation or authoritative restore procedure.

For a confirmed eligible object use only the approved exact `Restore-ADObject -Identity <guid> -Server <dc> -TargetPath <approved-parent-dn>` slice. Restore a deleted parent before its explicitly listed child, with separate bounded dependencies; never recursively recover an unknown subtree. Verify the original GUID/SID, intended parent/name, required attributes and group links on the relevant replicas. Inspect disabled/account state, protected flags, delegated ACLs and privileged membership before allowing use. Refresh tokens and perform the intended allowed and denied user/service checks. Membership links, trust relationships and applications need their own acceptance; object existence alone is partial evidence. If a restored account would gain unexpected privilege, stop and coordinate containment with the access owner rather than blindly deleting it again.

## GPO setting rollback

Distinguish the GPO GUID from the backup-instance ID. Select one trusted `Backup-GPO` instance by exact backup ID, original domain/GPO GUID, timestamp, protected path and digest; never restore "latest" by display name. Save the current GPO and independently export its links, order/enforcement, security filter/delegation, WMI association and canary baseline. GPO backup is not a backup of the entire directory, linked OUs or WMI-filter definitions.

`Restore-GPO -BackupId <backup-id> -Path <protected-directory> -Domain <original-domain> -Server <dc>` restores a backup to its original domain. The planned isolated fixture scenario is rollback of an **existing**, dedicated GPO; no live recovery result is claimed. The cmdlet documentation states it fails when the original GPO no longer exists: stop and use a separately rehearsed GPMC/specialist recovery plan for a deleted GPO. Do not promise that AD Recycle Bin alone restores a complete GPO: both GPC and GPT are required. Never copy a policy directory or edit GPT.INI to manufacture one.

`Import-GPO` is a different operation: it transfers backed-up settings into a destination GPO, retaining destination links/security filtering, and can need an explicitly reviewed migration table for domain-specific principals/paths. A cross-domain import or recreation changes identity and scope and is not an equivalent fallback for failed restore. Reapprove the exact destination, mapping and canary.

After restore reconcile AD and SYSVOL on both the write DC and relevant serving DCs; version numbers can advance during recovery, so compare intended policy contents as well as convergence. Re-read links, filters, WMI and permissions independently against the approved before-state; recreate a missing external link only as a separate scoped change. Process policy on the approved canary under the host owner's plan and prove both the setting and exclusion/denial. Preserve recovery timing, unresolved state and a compatibility-aware rollback choice. No live domain evidence means `partially_verified`, even when offline or Windows-host tests pass.
