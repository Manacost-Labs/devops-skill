# Incident flow

1. State observed symptom and scope; distinguish confirmed facts from hypotheses.
2. Check the user path and current release/change timeline.
3. Stabilize through the owning module with the smallest safe action.
4. Preserve evidence: timestamps, dashboards, logs, traces, change IDs and decision record.
5. Communicate current impact, owner, next update time and escalation need.
6. After recovery, record cause or bounded uncertainty, corrective actions and alert/runbook gaps.
