# Bounded EC2 launch

Use for an explicitly scoped `RunInstances` request, starting with one instance. Existing autoscaling, CloudFormation/CDK/Terraform ownership routes to that controller. Inventory caller account/partition, Region, subnet/AZ, AMI ownership and architecture, instance type, SGs, IAM instance profile, volumes/KMS, tags, metadata settings and public-IP behavior. Pin a launch-template **version**, if used. Resolve defaults into the reviewed request; never rely on a default subnet/group or floating template version. An instance role also requires the correctly scoped `iam:PassRole` permission.

## Preflight and launch identity

Query the actual regional EC2 purchasing-family vCPU quota and current usage, EBS volume/storage/IOPS quotas, ENI limits, subnet free addresses and any requested Elastic IP quota. Include temporary replacement capacity and resources created by dependent steps. Quota headroom is different from an AZ's available capacity. Distinguish `InstanceLimitExceeded`/quota errors, `InsufficientInstanceCapacity`, and throttling; moving Region/AZ, changing type or purchasing option is a new target/cost plan, not an automatic retry.

Persist the exact canonical `RunInstances` parameter digest, account/partition/Region/AZ, generated `ClientToken`, allowed count range, deadline and preexisting resource IDs **before** dispatch. This runbook uses `MinCount=MaxCount` for exact intended count. Set an explicit token; do not depend on a CLI/SDK auto-generated token surviving a process restart. Record the AWS request ID and reservation/instance IDs when a response arrives.

`RunInstances` token scope is regional when no AZ is selected, and zonal when `Placement.AvailabilityZone` or `SubnetId` selects an AZ. AWS permits the same token to create resources in another Region/AZ. The module therefore binds the token to the full original scope and exact parameters. Never change subnet/AZ/Region with that token or generate a fresh token to recover an uncertain launch. `IdempotentParameterMismatch` stops execution for reconciliation. A retry is allowed only for the identical retained request, within the documented idempotency behavior and still-valid authority, after the ambiguity checks below.

## Lost response and bounded observation

On transport timeout, 5xx or a killed CLI, assume resources might exist. Read `DescribeInstances` filtered by the retained `client-token` in the **same** account and Region, with all pages and all instance states. Reconcile reservation `OwnerId`, token, count, subnet/AZ, AMI, type, SGs, profile, volumes and every other material launch setting against the retained plan. Use audit/request evidence to resolve uncertain ownership. A temporary empty read or `InvalidInstanceID.NotFound` is compatible with eventual consistency; observe with bounded backoff before deciding. A full non-match at the deadline stays ambiguous and does not grant permission to launch again.

Observe exact returned instance IDs with `DescribeInstances`. AWS CLI v2's `ec2 wait instance-running --instance-ids ...` and `ec2 wait instance-status-ok --instance-ids ...` currently poll every 15 seconds and exit 255 after 40 failed checks; verify installed waiter behavior. Budget both waiters under the operation's overall deadline; reaching either budget means `partially_verified`, not permission to restart/terminate. `running`, EC2 status checks and application acceptance are distinct gates. Watch for terminal `shutting-down`/`terminated` or unexpected `stopping`/`stopped` states and capture reason codes.

## Partial success and recovery

Journal policy/profile, SG, launch, volume, address and attachment steps separately. If a later step fails, stop new mutations and enumerate exact surviving resources and charges. Retain a healthy instance when the owner chooses repair; termination requires its own authorized recovery action and data-loss assessment. Never terminate candidates merely because a tag/name matches. Before cleaning up a proven owned instance, check current ownership, termination protection, data retention, `DeleteOnTermination` and attached preexisting resources. EBS volumes, ENIs or Elastic IP allocations may survive; verify each intended cleanup individually. A failed/absent describe result does not prove termination or stopped billing.

## Optional offline inspection

`python cloud-aws/scripts/inspect-launch.py --checklist checklist.json --capture capture.json` reads local files only. `checklist` has exactly `account_id`, `partition`, `region`, `client_token`, `count`, `image_id`, `instance_type`, `subnet_id`, `security_group_ids`. It describes an observation subset, **not** the execution plan. `capture` has exactly `account_id`, `partition`, `region`, `response`; `response` is unmodified AWS CLI/SDK `DescribeInstances` JSON. Capture scope is supplied from separately retained caller/endpoint evidence; this helper cannot authenticate it. Keep capture timestamps, source identity and artifact digests in the operation ledger.

The checker rejects pagination tokens, malformed data, duplicate IDs, foreign owners/tokens/scope and mismatching checklist fields. Its observations are `unobserved`, `partial`, `pending`, `terminal` or `control_plane_match`; none proves absence, operation ownership, every launch setting, service readiness or authority to retry/clean up. Exit 0 means only that this subset matches running instances, exit 2 means unresolved observation, exit 1 means rejected evidence. Full plan comparison and fresh independent service checks remain mandatory.
