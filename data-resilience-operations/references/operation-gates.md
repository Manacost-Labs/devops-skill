# Data operation gates

Use this checklist after the target and operation type are confirmed.

| Operation | Required proof before change | Stop conditions | Verification |
|---|---|---|---|
| Backup assessment | Artifact identity, age, location, encryption, retention, chain/catalog status | Missing owner, unreadable metadata, unknown retention | Inventory reconciles with policy; no claim of recoverability |
| Isolated restore | Quarantined target, least-privilege reference, egress controls, capacity, integrity queries | Production consumers reachable, literal credentials, insufficient capacity | Restore completes; integrity and application checks pass; measured RTO |
| PostgreSQL physical/logical capture | Exact instance/database/global scope, compatible tools/extensions, tablespace mappings, snapshot/manifest and complete producer status | Partial scope mislabelled whole-instance, WAL/slot/I/O risk, unreviewed executable SQL or upstream configuration | Native artifact checks plus independent empty-target restore; object/data/application proof |
| PostgreSQL PITR | Valid base backup, continuous WAL range, target timestamp/LSN, timezone, recovery destination | WAL gap, ambiguous target time, overwrite without separate approval | Timeline/LSN and integrity verified; achieved RPO/RTO recorded |
| MySQL/MariaDB logical capture | Storage engines, DDL/quiescence, exact dataset/objects, tool/privileges and snapshot coordinates | Nontransactional/DDL inconsistency, missing objects, producer/compression failure, unapproved lock impact | Complete restricted artifact, native import plus application/object checks; hash alone is insufficient |
| MySQL/MariaDB binlog PITR | Proven base/coordinates, same source history, every log, exact transaction boundary and quarantine | Missing/corrupt/reordered log, wrong epoch, guessed timestamp, GTID ambiguity or active production consumers | Desired commits included, unwanted commit excluded, consistency and achieved point/time measured |
| MariaDB physical full/incremental restore | Compatible tools/keys, complete LSN chain, prepared work copy and stopped empty isolated target | Missing/wrong parent, corruption, unprepared data, nonempty target or incompatible product | Successful copy-back/start plus engine, object and application proof; original copies preserved |
| MySQL/MariaDB asynchronous cutover | Single-primary topology, independent fencing, lineage/required transactions, loss acceptance and client plan | Unknown writer, divergence, unsupported cluster surgery or ambiguous GTID history | One writer, client convergence, required data and service observation; failback separately planned |
| Redis RDB/multipart AOF recovery | Compatible tools, coherent manifest and every member, selected startup mode, captured point and expiry/clock evidence | Corrupt/truncated/missing artifact, concurrent incoherent copy, wrong selected persistence set, unsafe clients | Native validation plus actual load; required/excluded writes, types/expiry, persistence and application invariants |
| Redis distributed recovery planning | Exact replication/Sentinel/Cluster owner, shard/slot/epoch coverage, independent fencing and explicit loss bound | Missing shard, ambiguous writer/slot, controller conflict or unproven quorum/isolation | Separately rehearsed topology-specific recovery, client convergence and new-write persistence |
| Migration | Reviewed immutable plan, compatibility and lock analysis, tested recovery/cutover, fresh backup | Changed digest, unbounded rewrite/lock, unproven rollback | Schema/data invariants, clients, replicas, latency/errors, drift observation |
| Failover | Failure hypothesis, fencing, promotion target, replication lag/data-loss bound, failback plan | Split-brain risk, unknown writer, unacceptable lag | Single writer, client convergence, integrity, lag and service health |
| Retention deletion | Owner, policy, legal-hold check, exact allowlist, preview/digest | Hold or scope ambiguity, mutable/unbounded selector | Exact artifacts removed, protected set retained, evidence recorded |
| Masked restore | Approved masking rules, re-identification analysis, egress/identity isolation | Reversible identifiers, production credential path, unmanaged extracts | Sampling and invariant checks prove utility and masking boundaries |

Record sources, timestamps, target, actor/tool identity, artifact and plan digests, redaction state, exact changed resources, rollback result, and evidence references. Store raw sensitive evidence only in the approved access-controlled system.
