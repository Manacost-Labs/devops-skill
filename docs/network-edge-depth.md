# DNS, TLS and reverse proxy depth

Platform 0.14.0 expands the existing network-edge-operations module to 0.3.0. It distinguishes authoritative and recursive DNS/views/caches, actual served TLS identities and renewal ownership, effective proxy routes/trust, and state-aware recovery after a partial edge change. Provider/registrar writes, host/container orchestration, application/data recovery and protected authority retain their existing owners. Core modes, risk floors, exact gate/journal and separate destructive admission remain in force without repeated consent inside a valid envelope.

The runtime single-hop HTTP diagnostic pins its validated numeric destination instead of resolving again at connection time. It ignores proxy environment settings, retains strict TLS name/chain checking and SNI, refuses metadata/link-local/special targets even with the private-target override, never follows redirects, and suppresses URL path/query output. An explicit approved numeric endpoint and private CA file support origin/private-PKI observations. Neither flag grants authority. A 2xx/3xx response establishes one hop only; GET may have side effects, OS DNS and incremental headers are not hard wall-clock bounded, and body/application acceptance is separate.

## Required native CI

The operations smoke workflow adds **Edge / nginx DNS TLS recovery**, **Edge / caddy DNS TLS recovery** and **Edge / traefik DNS TLS recovery**. All run on disposable GitHub-hosted Linux runners with immutable image digests, hash-pinned Python test dependencies, synthetic private PKI and an owned internal Docker network. There are no host-published ports, live DNS/CA credentials, privileged containers, Docker socket mounts, production endpoints or public ACME orders. Containers have dropped capabilities, no-new-privileges, resource limits and ownership-checked cleanup. Private CA signing keys remain in host memory; only synthetic server keys reach their owned read-only fixture mount. The client trusts only the generated root when testing that chain.

Each engine exercises real CoreDNS UDP/TCP A/CNAME/NODATA/NXDOMAIN answers and TTL/SOA observations, strict TLS with the intended SNI/Host, the bundled helper with an explicit numeric endpoint, rejection of wrong hostname, unknown CA, missing intermediate and expired certificates, invalid pair preflight with the healthy route retained, served certificate rotation without a process/container restart, a valid but broken upstream producing 502 followed by recovery, a slow upstream producing 504, default-host isolation, spoofed client-IP handling and a redirect that the helper does not follow. Nginx and Caddy use their actual validation/reload commands; Traefik uses a separate isolated candidate for the invalid-pair test and actual file-provider reconciliation. Runtime versions are printed from the binaries, not inferred from a moving tag.

Authoritative fixture answers do not exercise a recursive cache, serve-stale, DNSSEC, registrar delegation or real global propagation. Manual generated leaf-pair activation is **not** an ACME renewal test; no public CA staging/production order, rate-limit recovery, real timer/deploy hook, revocation, client OCSP/CT or private-CA distribution is claimed. The network uses IPv4; production IPv6, CDN/LB/mTLS, firewall/provider enforcement, gRPC/WebSocket, existing-connection drain and multi-node partial failure need target-owner rehearsals. Guidance and fresh forward evaluation cover those decisions, not simulated production evidence. The synthetic upstream serves no business data and cannot prove application/schema recovery.
