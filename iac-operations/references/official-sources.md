Terraform/OpenTofu sources were refreshed 2026-10-30. Native state/recovery CI pins Terraform 1.17.1, OpenTofu 1.13.2 and separately pinned engine-native local 2.5.3 packages from their respective registries. Official release ZIP checksums are pinned; after bootstrap a checksum-locked filesystem mirror supplies the provider. Its unpacked platform lock is derived by the CLI from verified mirror bytes, then held readonly. Each engine uses separate synthetic state and local objects. Loopback HTTP state/lock and injected persistence failures do not certify cloud leases/IAM, production backend durability, KMS/key recovery, cross-engine migration or application/data rollback. See source-checkout `docs/terraform-operations-depth.md`.

The native fixture uses real Ansible modules and strategies with separate local directories for three synthetic inventory hosts. It proves orchestration and file-state behavior only; it does not certify SSH/WinRM, actual service readiness, load balancers, quorum, database rollback or production availability. Connection loss is injected through a test-only connection plugin. See the source-checkout test procedure in `docs/ansible-operations-depth.md`.

Version-pinned source checks explain the native HTTP boundaries: Terraform 1.17.1 [HTTP unlock client](https://github.com/hashicorp/terraform/blob/v1.17.1/internal/backend/remote-state/http/client.go) uses process-held lock information, while its [migration contract](https://github.com/hashicorp/terraform/blob/v1.17.1/internal/states/statemgr/migrate.go) preserves snapshot metadata only where both managers support it. Native tests verify actual requests and resource bindings; do not infer universal unlock or lineage guarantees from CLI flags.
